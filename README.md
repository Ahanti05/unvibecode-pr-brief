# UnvibeCode PR Brief (prototype)

**Problem:** many developers try [UnvibeCode](https://github.com/FinanceFlash/unvibecode) once and forget it.
**Idea:** bring its output to the place developers already visit every day, the pull request.

PR Brief turns an UnvibeCode review into one short comment on a pull request:

- which **business workflows** the change touches
- which **files to review first** (the code that depends on the change)
- a **low / medium / high** label

Every comment says "Generated by UnvibeCode", so the product name stays visible.

> Prototype for the UnvibeCode Engineering Challenge 2026 (Cohort 3, Track 2). Not an official UnvibeCode tool.

## Try it in 10 seconds (no install)
Needs only Python 3. Uses a small sample taken from a real UnvibeCode review of Flask.

```
git clone https://github.com/Ahanti05/unvibecode-pr-brief
cd unvibecode-pr-brief
python pr_brief.py --results examples/flask-sample.json --changed src/flask/helpers.py
```

Output (a pretend PR that changes `src/flask/helpers.py`):

> ## UnvibeCode PR Brief  `unvibecode: high-risk`
>
> 1 file(s) changed, 1 found in the Connected Code Map.
>
> **Business workflows touched**
> - Register a blueprint and its routes with an application / Serve files from a blueprint's configured static dir
>
> **Review these files first** (they depend on the changed code)
> - `src/flask/__init__.py` (11 links)
> - `src/flask/app.py` (6 links)
> - `examples/tutorial/flaskr/auth.py` (3 links)
> - `examples/tutorial/flaskr/blog.py` (3 links)
> - `src/flask/cli.py` (3 links)
> - `src/flask/sansio/app.py` (3 links)
> - `src/flask/blueprints.py` (2 links)
> - `src/flask/ctx.py` (2 links)
>
> **The changed code relies on**
> - `src/flask/typing.py`
> - `src/flask/wrappers.py`
> - `src/flask/globals.py`
> - `src/flask/signals.py`
> - `tests/conftest.py`
>
> _Risk label rule: dependents + 3 x workflows touched; docs/tests-only = low. Generated by UnvibeCode._

Try other files too: `src/flask/config.py` (medium risk, "Load application configuration" workflow) or `docs/conf.py` (low risk).

## Use it on your own repository
1. `python -m unvibecode review --repository <repo> --output out`
2. `python pr_brief.py --results out/<analysis-folder> --changed src/a.py src/b.py`
   or `git diff --name-only origin/main... | python pr_brief.py --results out/<analysis-folder> --changed -`

## How it works
- `connections.jsonl` (from the UnvibeCode results ZIP) says which file imports which.
  Files that import the changed code go into "Review these files first".
- `business-workflows.html` lists the files behind each workflow.
  If a changed file is one of them, the workflow is listed.
- Risk label: number of dependent files + 3 x workflows touched
  (4 or more = medium, 12 or more = high). Changes only in docs/tests/examples are low.

## In a pull request (GitHub Action)
`.github/workflows/unvibecode-pr-brief.yml` shows the plan: run UnvibeCode, list changed files, post the comment.
Next step: cache the review of the main branch so each PR run is fast (a full Flask review took about 1m20s).

## How repeat use would be measured
Comments posted per week, repositories that keep the Action on after 2 weeks, and reactions on the comment.

## Tests
```
python -m unittest discover tests
```

## Known limits
- The risk label is a simple rule, not a security verdict.
- Links come from UnvibeCode's map, so wrong links in the map show up here too
  (for example it lists `tests/conftest.py` as a dependency of `src/flask/helpers.py`).
- The GitHub Action file has not been run on GitHub yet.
- `examples/flask-sample.json` holds file names and links only (no Flask source code), from pallets/flask @ `49943b5`.
